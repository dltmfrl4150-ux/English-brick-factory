# 01. 개발 명세 (확정본)

사용자가 처음 작성한 개발 명세를 바탕으로, 이후 대화에서 확정된 결정사항을 반영한 최신본이다.
원본 명세와 다른 부분은 이 문서가 우선한다. 블록 분류는 `02_블록분류규칙.md`가 우선한다.

---

## 1. 최종 목표

사람이 큰 주제만 주면, 아래 전 과정이 자동으로 진행되는 "AI 자동화 팀"을 만든다.

1. 큰 주제 → 세부 대화문 주제 선정, 주간 업로드 계획표 작성 (사람이 계획표 승인)
2. 대화문 작성 → 영문 검토 → 한글 검토
3. 블록 분석 (영어학습용, 한국어학습용)
4. 영상 제작: 영어학습 채널용 / 한국어학습 채널용, 각각 롱폼 + 쇼츠
5. YouTube 롱폼·쇼츠, Instagram 릴스 업로드 (비공개)
6. 채널 분석 및 마케팅 (다음 주제 제안)

**구현 방식:** 콘텐츠 제작 팀은 독립 에이전트가 아니라 "Python 파이프라인이 역할별 AI 지시문을 순서대로 호출"하는 구조로 만든다.
순서·검증·파일 저장은 코드가 담당하고, AI는 생성과 분석을 담당한다. 매주 Windows 작업 스케줄러로 실행.

**현재 1차 목표:** 새 CSV를 입력하면 명세대로 롱폼·쇼츠가 렌더링되는 "브릭 학습 모드" 완성 (M3~M6).

## 2. 확정된 결정사항

| 항목 | 결정 |
|---|---|
| 개발 방식 | 기존 런처를 새로 만들지 않고, 같은 프로젝트에 "브릭 학습 모드"를 새 파일로 추가. 기존 엔진 재사용 |
| 기존 섀도잉 모드 | 코드는 건드리지 않고 그대로 둠. 기존 CSV는 폐기. 기존 모드 회귀 테스트 불필요 |
| 모드 판별 | CSV 헤더에 `block_text` 열이 있으면 브릭 모드 (`brick_csv.is_brick_csv`) |
| 영상 단위 | CSV의 **그룹(영아/유아/초등) 하나 = 롱폼 영상 하나** (영상당 5~10문장) |
| 복습 위치 | 각 영상의 모든 문장 학습이 끝난 뒤 STEP 3 복습 한 번 |
| 쇼츠 | 3분 이하. **STEP 3 복습 없음, STEP 2에서 영어 음성을 블록당 1회만** 재생. 같은 그룹 안에서 문장을 순서대로 채워 175초를 넘지 않게 나눔 (그룹당 2~3편 예상) |
| 음성 여백 | 모든 음성 앞 0.3초만. 음성 뒤 유지 여백 없음 (명세의 대기 배수가 실제 대기시간) |
| 학습 언어 | `learn_lang` = `en`(영어학습) / `ko`(한국어학습). 같은 렌더러, 방향만 반대 |
| 업로드 | 항상 비공개 업로드 후 사람이 확인하고 공개 |

## 3. CSV 형식 (한 행 = 블록 하나, UTF-8 BOM)

| 열 | 내용 | 위치 |
|---|---|---|
| topic, target, situation, learn_lang | 주제, 대상, 상황, 학습 언어 | 파일 첫 행만 |
| group, sentence_id, speaker | 그룹, 문장 번호(파일 전체에서 고유), 화자 | 모든 행 |
| block_order, block_text, block_meaning, category | 블록 순서(1부터), 학습 언어 표현, 뜻, 색상 카테고리 | 모든 행 |
| full_sentence, full_translation, direction | 전체 문장, 전체 번역, 연출 메모 | 각 문장의 첫 블록 행만 |
| needs_review | 확인 필요 블록만 `Y` | 해당 행 |

- 영어학습용: block_text = 영어, block_meaning = 한국어 뜻, full_translation = 한국어
- 한국어학습용: block_text = 한국어, block_meaning = 영어 뜻, full_translation = 영어
- 블록을 공백으로 이으면 full_sentence와 정확히 같아야 한다 (`brick_csv.py`가 검증).
- 블록 뜻과 전체 번역은 별도로 관리하고 섞지 않는다.
- 블록 뜻의 `~`(예: `~도`)는 화면에만 표시하고 음성에서는 뺀다 (`Sentence.meaning_prefix`).
- 연한색/진한색은 CSV에 저장하지 않는다. 코드가 계산한다 (`assign_shades`).
- 향후 AI 분석 결과에는 role, confidence, review_reason 열을 추가할 수 있다. 로더는 모르는 열을 무시한다.

## 4. 영상 흐름 (롱폼, 그룹 하나 기준)

모든 대기시간은 앞뒤 무음을 제거한 실제 음성 길이 기준. 아래 숫자는 모두 설정값으로 바꿀 수 있어야 한다.

> **화면 표기 (2026-10-30 사용자 수정):** 화면에는 블록 학습을 `STEP 1 블록학습`, 이어서 말해보기를 `STEP 2 이어서 말해보기`로 표시한다
> (아래 문서의 STEP 2 → 화면 STEP 1, STEP 3 → 화면 STEP 2). 두 단계 사이에 `STEP 2 / 이어서 말해보기` 제목 카드 1초(`step_title_ms`).
> 상단 소제목은 `학습종류 | 주제 STEP N 단계명` (예: `육아영어 | 아침 깨우기 STEP 1 블록학습`). 학습종류는 CSV 첫 행의 선택 열 `learn_type`.
> 마이크 안내 아이콘은 `assets/mic.png`.

### STEP 1 · 주제 소개
- 화면: 주제(크게), 그룹 캡슐, 대상, 상황
- 음성: 주제만 (뜻 언어 음성. 영어학습용이면 한국어로 "아침 깨우기")
- 최소 3초 유지

### STEP 2 · 문장별 블록 학습 (모든 문장 반복)
| 순서 | 화면 | 음성 | 대기 |
|---|---|---|---|
| 2-1 | 위: 전체 번역 / 가운데: 모든 블록 빈칸(색만) / 아래: 마이크 + "영어로 말해보세요" | 전체 번역 | 전체 정답 음성 길이 × 1.0 |
| 2-2 | 1번 블록 아래 뜻 표시 | 누적 뜻 1 (1번 뜻) | 3초 카운트다운 |
| | 1번 블록에 학습 표현 공개 (팝업) | 누적 문장 1 | × 1.5 → 같은 음성 재생 → × 1.5 |
| 2-3 (k ≥ 2) | k번 블록 아래 뜻 추가 (이전 블록·뜻 유지) | 누적 뜻 k (1~k번 뜻) | 5초 카운트다운 |
| | k번 블록 공개 | 누적 문장 k (1~k번 블록 이은 문장) | × 1.5 → 재생 → × 1.5 |

- 누적 뜻 예: "잤어?" → "잤어?, 푹" → "잤어?, 푹, 어젯밤에" (블록 뜻을 ", "로 이음)
- 누적 문장 예: "Did you sleep" → "Did you sleep well" → "Did you sleep well last night?"
- 블록이 하나뿐인 문장은 2-1 → 2-2로 끝난다.
- **2026-10-30 수정:** 누적 문장 음성은 1회(재생 → × 1.5 대기)만 재생하고, 마지막 블록(완성 문장)만 2회 반복한다.
  마지막 블록의 누적 뜻 음성은 블록 뜻을 이은 문장 대신 원래 번역(full_translation)을 읽는다
  (예: "일어나야지, 지금" → "지금 일어나야지"). 영어학습·한국어학습, 롱폼·쇼츠 모두 같다.
- 완성 문장 2회째는 바로 반복하지 않고: 원래 번역(상단 문장) 음성 → 정답 음성 길이 × 1.0 대기
  (`final_translation_wait_factor`) → 정답 음성 → × 1.5 대기.

### STEP 3 · 이어서 말해보기 (모든 문장 반복)
1. 전체 번역 + 모든 블록 빈칸 (뜻 표시 없음), 마이크 안내
2. 전체 번역 음성
3. 전체 정답 음성 길이 × 1.5 대기
4. 모든 블록 동시 공개
5. 전체 정답 음성
6. 1초 대기 → 다음 문장

### STEP 4 · 아웃트로 (약 4초)
- 영어학습용: "구독과 좋아요 누르고 / 같이 매일 연습해요!" / 한국어학습용: "Like & subscribe / and practice with us every day!"
- 좋아요·구독 버튼이 나타나고 차례로 눌리는 애니메이션 (`brick_frames` outro의 `t` 0→1)

### 쇼츠 흐름
STEP 1(짧게) → STEP 2(영어 음성 블록당 1회, 재생 후 × 1.5 대기 1회) → STEP 4. STEP 3 없음.

### 설정값 (config.json `brick` 항목으로 추가 예정)
| 키 | 기본값 |
|---|---|
| lead_pad_ms | 300 |
| intro_min_ms | 3000 |
| full_ko_wait_factor | 1.0 |
| first_block_countdown_s | 3 |
| next_block_countdown_s | 5 |
| en_wait_factor | 1.5 |
| block_repeat_long / final_repeat_long | 1 / 2 (2026-10-30 수정: 누적 문장 1회, 완성 문장만 2회) |
| block_repeat_shorts / final_repeat_shorts | 1 / 1 |
| review_wait_factor | 1.5 |
| review_after_ms | 1000 |
| outro_ms | 4000 |
| shorts_target_s | 175 |

## 5. 화면 규격 (M2 승인본, `brick_frames.py`)

- 배경 `#2C2C2C`, 블록 안 글자 흰색, 둥근 모서리(8px) 색 블록, 블록 간격 16px
- 블록 폭 = max(학습 표현 폭, 뜻 폭) + 여백. 처음부터 최종 크기로 그려 공개 시 화면이 흔들리지 않음
- 블록 아래 뜻: `#D9D9D9`. 상단 진행 라벨 `#AEAEAE`, 화자 `#7F7F7F`, 전체 번역 `#D9D9D9`
- 16:9 카운트다운: 우측 하단 회색 원 + 숫자
- 9:16 카운트다운·안내: Shorts/릴스 우측 버튼과 하단 제목 영역을 피해 블록 아래 가운데
- 블록이 화면 폭을 넘으면 먼저 글자를 줄이고(최소 크기까지), 그래도 넘치면 줄바꿈
- 한국어학습용은 화면 문구·화자·그룹명을 영어로 표시 (`NAMES`, `UI`)
- 색상표는 `02_블록분류규칙.md` 참고

## 6. 음성 배정

기존 런처의 음성 설정 4종(en_mom, en_kid, ko_mom, ko_kid)을 그대로 사용한다.

| | 영어학습용 (en) | 한국어학습용 (ko) |
|---|---|---|
| 블록 표현 / 전체 문장 | 영어 음성 (화자별) | 한국어 음성 (화자별) |
| 블록 뜻 / 전체 번역 / 주제 | 한국어 음성 (화자별, 주제는 엄마) | 영어 음성 (화자별, 주제는 엄마) |

화자 `엄마` → mom, `아이` → kid. 그 외 화자는 mom 음성을 쓰고 로그에 경고.

## 7. 기존 코드 분석 요약

| 파일 | 역할 | 브릭 모드에서 |
|---|---|---|
| `shadowing_render.py` | CSV → Edge TTS → pydub 오디오 타임라인 → PIL 정지 프레임 → ffmpeg MP4. 구 섀도잉 흐름(Phase 1~4) | **재사용:** `synth`, `tts_path`, `trim`, `room_tone`, `Timeline`, `encode`, `ease_out_back`, `FPS`, `SAMPLE_RATE`, `BUILD`, `TTS_DIR`. **사용 안 함:** `load_csv`, `build_timeline`, `render_frame`, 구 팔레트 |
| `launcher.py` | tkinter GUI, 작업 스레드 + 큐로 로그·진행률 | M6에서 CSV 형식 자동 판별 후 브릭 렌더 함수 호출 추가 |
| `uploaders.py` | YouTube Data API v3 업로드(OAuth, 이어받기), Instagram Graph API 릴스(재개형 업로드) | 그대로 사용. 이후 재시도·게시 이력 추가 예정 |
| `thumbnail.py` | 롱폼 썸네일 | 당분간 그대로 |

주의할 구조:
- `Timeline.show()`는 모듈 전역 `render_frame`을, `Timeline.play()`는 전역 `LEAD_PAD_MS`, `HOLD_AFTER_VOICE_MS`를 직접 읽는다. 브릭 모드는 `Timeline`을 상속해 이 두 메서드만 재정의한다 (기존 파일 수정 없음).
- `apply_layout()`, `apply_timing()`은 모듈 전역을 바꾸므로 렌더링은 한 번에 하나씩 순차 실행한다.
- `build/frames/`, `build/tts/` 캐시를 지우는 코드가 없다. 브릭 모드 프레임은 `build/frames_brick/`에 따로 캐시한다.
- 구 모드 CSV 파서는 블록을 열 순서로 이어서, 문장 순서가 열 순서와 다르면 화면과 음성이 뒤섞이는 버그가 있다. 구 모드는 폐기 예정이라 고치지 않는다.
